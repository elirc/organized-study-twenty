# 08 — Interview Prep

Target: **mid-level fullstack JS/TS interviews.** The edge this module gives you: nearly every answer is anchored to real code you can describe concretely, instead of recited definitions. Interviewers consistently upgrade candidates who say "in a CRM codebase I've worked deep in, the webhook job does X, and the tradeoff was Y."

## How mid-level loops are typically structured

1. **Screen (30–45m):** JS/TS fundamentals + one small coding exercise → [01-js-ts-node-deep-dive.md](01-js-ts-node-deep-dive.md)
2. **Technical deep-dive (60m):** walk through a system you know → [04-system-design-from-this-repo.md](04-system-design-from-this-repo.md) + [03-architecture-and-patterns/06](../03-architecture-and-patterns/06-architecture-critique.md)

Frontend-leaning loops add a framework round → [02-frontend-framework-questions.md](02-frontend-framework-questions.md); API/backend-leaning loops add data modeling → [03-api-and-data-modeling-questions.md](03-api-and-data-modeling-questions.md). ## The golden rule

Answer every technical question with **concrete example + tradeoff + failure mode**, never a bare definition. Formula: *definition in one sentence → "for example, in Twenty…" → the tradeoff the team accepted → what breaks when it's done wrong.* That four-beat answer is what "mid-level" sounds like; the junior version stops after beat one.

Use this repo as your portfolio: you have traced flows (module 01), a critique with prioritized risks (module 03), debugging narratives (module 05), and — if you did the tickets — real diffs. In the interview, don't claim employment at Twenty; say "an open-source CRM codebase I've studied deeply and contributed to" — verifiable and impressive.
